# deployment_record

The typed, versioned, provenance-carrying deployment artifact
(`deployment_record.json`) specified in `docs/deployment_record_schema.md`:
**a deployment is a schedule** — ordered passes over the alternating
NeuralOps/ComputeOps structure — and the record is the join of the run's
formerly-disconnected measured surfaces (schedule/placement census, layout and
crossbar utilization stats, SANA-FE physics, accuracy reads + certificates).
It is a join and a registry, not new measurement.

Discipline: all schema types are frozen dataclasses with JSON-safe
`to_dict`/`from_dict`; `from_dict` rejects unknown fields and wrong
`format_version` (the `CostRecord.from_dict` discipline — evolution is a
version bump + explicit migration, never silent tolerance). Every modeled
value carries a `(low, nominal, high)` band with a written basis; no proxy is
ever presented as a measurement.

## Key files

| File | Role |
| --- | --- |
| `platform_physics/` (incl. `host_calibration.py` [H3b]: measure THIS host's ComputeOp-shaped MACs/s + RAPL package power where readable into an override-ready block with `evidence_kind: measured` — the host terms stop being the estimated 100x wildcard) | The TARGET's half of the cost model: per-unit physical constants a vendor declares, which the cost model multiplies by the quantities the record already seals. The record counts (cells, MACs, spikes, hops, bytes, passes, timesteps); this names what each one costs in joules, square metres and seconds, so an absolute Area/Energy/Latency/Throughput number is attributable to a real chip instead of to a framework default. `vocabulary.py`: the closed constant list AS DATA — `(key, group, dimension, display_unit, multiplicand, doc)` per row, where `multiplicand` names the recorded quantity the constant is priced against, because a bare "energy" number is unusable and the pairing belongs in the declaration rather than at a pricing site. It also declares `SUPERSEDES`: a published AGGREGATE already contains the decomposition it supersedes, so `constants.resolve_supersessions` drops the absorbed terms and pricing can never charge both. The rule stays for a target that publishes only a whole-chip average, but NO shipped profile prices from `e_synaptic_event_total` any more: an average is a POINT model — it folds static power into a per-event rate, so it is exact where it was measured and wrong elsewhere (TrueNorth's own 26 pJ/event overshoots its published 96 Hz measurement by 256%, ODIN's 12.7 pJ/SOP undershoots its published biological-time point by 76%). Every profile now declares a MARGINAL per-event energy with static power beside it, and `correlation/` is what proves the difference. Execution POLICY (overlap, residency-across-batch) is deliberately NOT here — physics is banded numbers only. `constants.py`: `PhysicsConstantSpec` + the built registry, `spec_for`/`keys_in_group` (group order IS the wizard panel order). `profile.py`: `PhysicsConstantValue` — the declared band in its declared unit PLUS its evidence, where `evidence_kind ∈ published/datasheet/derived/estimated` each REQUIRE their own field (a citation, a shown derivation, a written rationale), so an unevidenced number cannot be constructed; the SI `band` is a PROPERTY, never a stored field, so the declared and canonical forms cannot drift. `PlatformPhysics` has `has`/`band`/`missing`/`declares_all` and deliberately NO `get(key, default)`: an undeclared constant is ABSENT, which disables exactly the objectives that need it and may never be silently defaulted to a framework number masquerading as vendor data. `loader.py`: strict JSON reading (unknown constant, unknown field and wrong `format_version` all raise), the `source_ref` indirection — `sanafe_preset:<preset>:<field>` materializes a constant from the in-repo SANA-FE per-event presets so a number that already has a home is REFERENCED rather than forked — and `apply_overrides`, which requires an operator to say WHY they deviate and marks the result so reports and the wizard show the departure. `conversion.py`: the target's DATAFLOW, for the one quantity no record counts — an analog accelerator's cost is dominated by data conversion, but the conversion COUNT is a function of the target's geometry, converter sharing and input bit-slicing rather than of the workload, so the target declares a named model and the model derives `adc_conversions`/`adc_count` from quantities the record already carries. `digital` (the default) yields ZERO, which is a fact about a digital chip rather than an absence; `bit_sliced_crossbar` is the ISAAC/PRIME dataflow, where a partial column still costs a whole integration (the division rounds UP, since rounding down would price a read the chip performs at nothing). Derived counts are MODELED, never measured, and a view's own quantity always wins over a modeled one — a model may only ADD what the record could not know. The declaration is validated at LOAD time, so a dataflow the model cannot describe fails when the profile is read rather than as a conversion count nobody can defend at pricing time. `registry.py`: profiles discovered as data from `profiles/`, resolved via `__file__` so the cwd never matters; a vendor adds a target by dropping in `<name>.json` + `<name>.md` with no `src/` edit, and a profile whose description file is missing refuses to load. Its `profiles/` subdirectory is DATA, not code: one `<name>.json` of declared constants plus the `<name>.md` description file carrying citations, per-constant derivations, estimate rationales and the validity domain in prose. Five ship: `truenorth` (silicon, the reference, characterized at the 0.8 V corner where Akopyan's Fig. 17 firing-rate sweep lets the MARGINAL per-event energy be separated from static power by regression), `loihi` (SIMULATION — Davies 2018 Table 2 is explicitly pre-silicon SDF+SPICE, and the profile declares no `t_cycle` because Loihi is asynchronous with no fixed timestep, so it honestly cannot back latency, throughput, or the static energy that accrues over a wall it cannot price), `odin` (silicon, 28 nm FDSOI single core — the target whose paper publishes the affine power model outright, `P = P_leak + P_idle x f_clk + E_SOP x r_SOP`, and the reason the library stopped pricing from operating-point averages), `isaac_like` (SIMULATION, analog), and `generic_estimated_22nm` (every constant `estimated`, named so nobody mistakes it for a chip, existing so a first-cut study can run and so the estimated-evidence path is exercised by something unmistakable). `truenorth` is the reference profile — every constant published or derived-with-arithmetic-shown from Merolla 2014 (incl. Supplementary S1–S13) and Akopyan 2015, all measured on silicon, with the research pass in `docs/research/physics/`. Zeros are declared FACTS there (a fully digital chip has no ADC and no analog programming spread), distinct from absent constants, which mean "this target has not said". |
| `units.py` | The dimensional-unit SSOT, above BOTH halves of the cost model because a constant and the quantity it multiplies must agree on what a unit means. A `Unit` carries a DIMENSION (energy/area/time/power/data/dimensionless) and an SI scale, so a vendor may declare in whatever unit they like (23600 fJ and 23.6 pJ are one constant) while a wrong-DIMENSION declaration fails loud; dimensionless symbols (`bit`, `levels`, `fraction`) are display labels that never rescale, which keeps a bit WIDTH from ever being converted like a DATA payload. It lives here rather than inside `platform_physics/` so that `quantities/` can import it without dragging the physics loader in behind it — the cycle that import order used to hide. |
| `quantities/` | The quantity catalog (C0): every priceable multiplicand as data — `spec.py` declares `QuantitySpec{key, dimension, unit, doc}` rows (the closed catalog the physics vocabulary's `multiplicand` column now references, pinned by test, so a pricing formula can never name a number nobody produces) plus `QuantityValue{value, provenance ∈ measured/static/modeled}` and the `Quantities` mapping, where ABSENCE is meaningful throughout (`get` raises; no default). The catalog keeps the two MAC censuses distinct on purpose: `macs` is the AS-MAPPED site count (replicas really fire — the energy multiplicand) while `total/onchip/host_macs` is the LOGICAL replication-free split census. `from_record.py` extracts the measured plane of a sealed record (reprogramming quantities count REPROGRAM passes only — a resident pass sends nothing; `noc_total_hops` derives from the sealed link loads rather than being re-sealed; `synaptic_events` is deliberately unclaimed — `total_spikes` counts emissions, not synapse arrivals). `from_candidate.py` extracts the static facts a search candidate can honestly answer (`CandidateQuantityContext` carries the run declarations the layout does not; `synaptic_events` is MODELED from the declared activity factor — the EDA switching-activity discipline — and says so). `probe.py` is the all-keys strictly-positive placeholder for capability questions only. |
| `correlation/` | SILICON CORRELATION: does a declared profile reproduce the measurements its own papers publish? The acceptance a physics profile must clear before it ships, and the thing that separates a characterization from a guess with citations. `case.py`: `ReferenceCase` — a published operating point as DATA, carrying the number, its citation AND the sentence it appears in, the workload census the paper's own structural statements determine, a per-entry `census_sources` map (a census number with no stated source is a fitted parameter in disguise, so construction refuses it), and an `independence` flag separating a genuine prediction from a row that re-derives the point its own constant was divided out of. `run.py`: prices the census with the named profile and scores each axis; an axis the physics REFUSES scores as a total miss, never as agreement, and a case may restate its operating point only by overriding a constant the profile already declares — never by introducing one. `derived.py`: the axes a paper prints that the pricer expresses as a ratio of two priced terms (`average_power_mw` = energy / latency), kept here so the four headline axes every registry and study table is keyed on stay unchanged. `library.py`/`report.py`: the shipped cases and the correlation table. `cases/` is DATA: seven cases over three devices, worst error 14.5%, all inside ±25%. |
| `study.py` | [C7] The cross-platform comparison: ONE workload census priced by many declared targets — the question a chip designer actually asks. Because the pricer is one pure function of (quantities, physics), this is a fan-out over profiles rather than a second cost model. Two disciplines it ENFORCES rather than documents: an axis a target cannot back is ABSENT with its reason, never zero — on a minimized axis a zero would read as the best possible result, so Loihi's missing `t_cycle` must not make it the fastest chip in the table; and every row discloses its evidence (measurement kind plus a per-kind constant count), with a table mixing bases flagged explicitly, because a silicon measurement beside a pre-silicon simulation is a legitimate comparison and an illegitimate one to report silently. `scripts/cross_platform_study.py` runs it over a sealed record. |
| `fidelity.py` | [C4] The estimate-vs-signoff correlation, the EDA discipline this whole program is shaped by: what the SEARCH predicted against what the RUN measured, axis by axis. One pricer serves both completenesses, so the same objective keys carry the same term names on both sides and this is a ZIP rather than a second model. `in_band` is a verdict only where a BAND was predicted — a point prediction is not a claim about a range, and reporting one as out-of-band would invent a tolerance nobody declared — and relative error is measured AGAINST the measurement, since the measurement is the reference and the prediction is what was wrong. Either side may be absent and both cases are recorded: an axis only the record answers is what the search could not see. REPORT-FIRST by decision: it gates nothing numeric, because the tolerances are a decision to make ON this evidence rather than before it; the STRUCTURAL equality (the searched pass count == the deployed one) is gated where it belongs, in the mapping tests. |
| `fidelity_build.py` | [C4] Builds a report from a sealed record plus the candidate view of its own configuration — one registry read per side over the catalog's own axis order, and the predicted BAND recovered from the candidate's own priced term. `emit_fidelity_report` writes `fidelity.json` only when there is a prediction to compare against: an unsearched run has nothing to correlate, which is different from a fidelity of zero and is written as nothing at all. `scripts/fidelity_summary.py` aggregates the artifacts across run dirs. |

## Dependencies

Near-leaf: may import `mapping`, `chip_simulation`, `certification`,
`config_schema`, `common` — NEVER `pipelining`/`search`/`gui` (the mirror
contracts to `mapping` types are enforced by tests).
Consumers (stage 2): the mapping pipeline steps and the spike-count gate emit
fragments through the pipeline cache (`deployment_record_scm` /
`deployment_record_hcm`) using the `build/` converters. Stage 3: the nevresim
Simulation step emits `deployment_record_nevresim` (probe read in
`AccuracyReadRecord` shape, the driver's measured total-output-spikes figure,
host-op walls from `chip_simulation.hybrid_run.stage_timing.StageTimer`).
Stage 4: the terminal `DeploymentRecordStep`
(`pipelining/pipeline_steps/verification/deployment_record_step.py`) re-types
the cached fragments, joins the SANA-FE report via `build/from_simulators.py`,
seals against the plan (`SealPlanView` adapter in the step's assembly module),
writes `deployment_record.json` atomically, and emits the legacy
`cost_record.json` via `cost/legacy_projection.py` IFF the SANA-FE fragment is
present. Stage 5 adds `cost/`'s `DeploymentCostModel` as a pure reader of a
