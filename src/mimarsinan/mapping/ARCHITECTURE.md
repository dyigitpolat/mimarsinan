# mapping/ — PyTorch model → IR → packed hardware cores

Takes the mapper graph produced by `torch_mapping` (a `ModelRepresentation` of
`Mapper` nodes) and lowers it to deployable hardware: `IRMapping` materializes
weights into an `IRGraph` of `NeuralCore` / `ComputeOp` / `WeightBank` nodes,
pruning compacts and segments that graph, and packing bins the resulting soft
cores into `HardCore`s under `ChipCapabilities` constraints (flat or hybrid
multi-stage). Latency scheduling, shape-only layout estimation (for search),
layout verification, and chip export round out the path from trained model to
simulator-ready chip description. Design notes live beside the code in
`FIRING.md` (firing-mode contract) and `LATENCY.md` (which latency engine to
use when).

[W4b-2] The same package carries CONSTANT-LATTICE PROPAGATION (config key `elimination_constant_folding`: full DEFAULT / off kill-switch, forced off by `identity_only` transfers), which generalizes "dead" to "carries a known value every timestep": the lattice is `TOP > CONST(c)` over structural lines with one-way descent (`constant_lattice.py` — an OFF axon reads 0.0, an ALWAYS-ON axon reads 1.0, an ELIMINATED producer column reads 0.0, so W4b-1 elimination IS the CONST(0) case rather than a separate mechanism, and a non-monotone re-derivation RAISES). ONE generic ComputeOp rule (`constant_transfer.py`): output `o` is CONST iff every input in `region(o)` is CONST — `region` being the W4b-1 `LivenessTransfer` relation, or the whole input vector for OPAQUE ops — with the value obtained by EXECUTING the op's own seam AT THE DEPLOYMENT DTYPE (`ir/deployment_dtype.py`) under three bit-exact agreement probes (determinism, batch-size independence — this is what refuses a `Linear`, whose GEMM reassociates differently from the batch-1 GEMV — and eval/as-deployed mode independence), a deployment-dtype CARRIABILITY gate (a constant the deployment cannot represent exactly never sat on that line, so probing the rounded value is refused), and two distinct fillers on the TOP inputs, so an under-reporting relation degrades to TOP instead of to a wrong constant; zero-preservation is NOT required, so `sigmoid(0)=0.5`, `LayerNorm(0)=bias`, attention and residual joins all fold. There is no cross-precision comparison: the constant IS the deployed value by construction. Each fold is then CLASSIFIED with the `is_on_grid` SSOT as grid-certifiable or execution-exact-only (`GELU(c!=0)`), and the split is surfaced as counts on the ledger's `constant_fold` attribution — the refusal is legible, and constants are never snapped onto the grid. The exact NeuralCore fold (`constant_core.py`): a CONST(c) axon row's contribution `c*W[r,:]` moves onto the core's EXISTING constant carrier — an always-on axon row (the crossbar bias encoding `chip_export` already folds into `hardware_bias`) or an owned `hardware_bias` vector, never an invented one — and row `r` is then eliminated exactly; a column all of whose contributing rows are eliminated/folded emits `(W[carrier,j]+b_j)/theta`, which is why BIAS_ONLY collapse (the 1x1 core deleted, its constant folded onward) falls out of the lattice instead of being a special case. Bank-backed cores READ their carrier (they can still be CONST producers) but never WRITE it: bank rows are shared physical structure removed by the W3c intersection rule, so a per-instance bias fold would double-count. Non-zero folds are additionally gated on the chip domain (`constant_policy.py`): exact only in the value/MVM domain, because a rate-coded spike train matches a per-timestep bias only in its window integral — CONST(0) folding stays exact in every domain. Arm semantics: masked never folds, closure sweeps once with `cross_core=False` (a CONST line kills its readers, but discovering a constant COLUMN is emergent deadness), cascade sweeps to fixpoint; the ledger gains a `constant_fold` attribution category carved out before the arm-difference buckets, and `graph/constant_reanalysis.py` is the PURE retrospective entry point that re-harvests a stored IR + seeds at zero GPU cost |

## Negative value boundaries

A host `ComputeOp` feeding a neural segment crosses a value->spike boundary,
and the `[0,1]` spike-encode clamp is the only lossy operation there. Two
mechanisms make that boundary lossless, selected by `negative_value_shift`
(`support/negative_boundary.py`):

- **on (default)** — `apply_negative_value_shifts` derives a calibrated
  per-channel positive shift `s = max(0, -min)` and pre-corrects the consuming
  perceptron's bias (`B - W*s`), so the next activation absorbs the shift
  exactly. Mapping structure is unchanged. A `ComputeOp -> ComputeOp` seam has
  no bias to correct and fails loud.
- **off** — `subsume_forward_negative_boundaries` moves the consuming
  perceptrons onto the host (`is_encoding_layer`) until a node that
  structurally cannot emit a negative value absorbs the range (ReLU, LIF, a
  non-negative clamp: `value_domain.produces_nonnegative_values`). It changes
  no weights; a host op that absorbs nothing is crossed, since it clamps
  nothing either. Leaving no on-chip segment fails loud.

`apply_negative_boundary_policy` runs the chosen mechanism and then re-checks
`lossy_negative_boundaries` from the calibrated minima: a negative boundary
that an on-chip segment would still encode raises. Silent clamp corruption is
therefore not authorable from either position. Both mechanisms share one
calibration (`calibrated_compute_op_minima`) and inherit its coverage caveat -
a boundary that stays non-negative on the calibration set but dips below zero
on unseen data still warns at runtime (`warn_once_lossy_negative_clamp`).
